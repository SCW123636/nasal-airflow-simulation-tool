# 方法：DICOM → 气道 STL → CFD

本文只写**已实测**的做法与参数。设计推导与实测结果分开标注，凡标注「实测」的都有对应产物与复验命令。

## 0. 适用范围：先判断这一例该不该走自动链路

自动链路只对「正常例」承诺无人值守。任何一条不满足即转人工，**不在本方法范围内**。

| # | 条件 | 判据 | 实现位置 |
|---|---|---|---|
| N1 | 有可用轴位原始序列 | `ImageType` 含 `ORIGINAL` + `AXIAL`，in-plane ≤ 0.8 mm | `batch27_series_choice.py` |
| N2 | 四标签非空 | `nasal_cavity_left/right`、`nasopharynx`、`oropharynx` 体素数 > 0 | `nasal_pipeline.py:mask_check` |
| N3 | 空气腔非空 | 标签并集 ∩ HU < −300 后体素数 > 0 | `batch27_surface.py` |
| N4 | 表面闭合 | marching cubes 后 `boundary_edges == 0` | `batch27_surface.py` |
| N5 | 提案可用 | 三开口有 `point_lps_mm` + `normal_lps` | `auto_anatomy_landmarks.py` |
| N6 | 开口面积入带 | 鼻孔 ∈ [40,140] mm²、口咽截断出口 ∈ [10,600] mm² | `auto_opening_pipeline.py` |

**N6 的出口带为什么是 [10,600] 而不是解剖带**：我们的出口是扫描 FOV 底面的**工程截断面**，不是 choana。它的面积由扫描范围与局部气道轴倾角共同决定，没有解剖参考值。这条带只用来抓病态失败（被裁没、或面积失控），**不用于验证解剖正确性**。曾经的鼻咽出口带 [120,500] 会让一个只是扫描视野偏小的例被判失败——这是真实的误判，已废弃。

## 1. 五步链路

```
① 选序列    batch27_series_choice.py     → 每例一个 DICOM 目录
② 分割      ts_nasal_seg.py --batch-dir  → ct.nii.gz + masks/*.nii.gz
③ 定位提案  auto_anatomy_landmarks.py    → landmarks.json（三点位）
④ 建表面    batch27_surface.py           → source_surface.vtp
⑤ 开口裁切  auto_opening_pipeline.py     → auto_placed.vtp + 逐例报告
```

单一入口 `nasal_pipeline.py` 把五步串成子进程。**每一步都可单独重跑**，且会跳过磁盘上已有的产物——分割在 CPU 上约 136 s/例，重跑代价不小。子进程隔离的另一个原因是一步崩溃不能把整批带走。

## 2. 各步实测参数

### ② 分割

- TotalSegmentator `head_glands_cavities` 任务，只取鼻腔相关标签。
- 阈值 **−300 HU**。−350 / −400 属验证项，不在生产路径静默切换。
- 中间产物必须落**纯 ASCII 路径**。ITK 读写非 ASCII 路径会报 `nifti library failed to write image`，这是实测踩过的坑。

### ③ 定位提案

产出的三点位**仅供作搜索起点，不是临床结论**。

### ④ 建表面

- 四标签并集，再 **∩ HU < −300**。这一刀去掉分割在骨壁上的部分容积体素；不做会明显更厚更糙。
- marching cubes 在体素空间做，再套完整 LPS 仿射。

### ⑤ 开口裁切（v2：按端盖实际面积二分）

沿平面法向二分，直到**生产 `clip_and_cap` 实际产出的端盖面积**达到目标：

| 开口 | 目标 | 备注 |
|---|---|---|
| 鼻孔 L / R | 80 mm² | 成人参考 50–100 |
| 口咽截断出口 | 250 mm² | 工程截断；实际由 FOV 决定，仅作搜索目标 |

- 三开口**坐标下降**，≤3 轮。实测第 2 轮即收敛，末轮位移 0.0 mm。
- 每开口 9 次二分；搜索窗按起点分档：`reviewed` 3 mm / 2⁹ ≈ 0.006 mm。
- 搜索起点默认 `reviewed`（即定位阶段提出的解剖平面）；只有该处端盖不足目标时才位移。
- 若锚点平面自身端盖已超带上限，回退 `onset` 起点并在报告写 `origin_downgrade`，**不静默换起点**。

> 为什么不用 `onset` 作默认起点：`onset` 的判据是「截面**总面积**首次达 50 mm²」，而端盖目标是 80/250，相差 5 倍。实测 ROI 盒沿法向负侧储备只有约 1.15 mm，于是 `|onset| ≳ 1.25 mm` 的开口在起点处盒内零种子，直接失败。临界落在 push ∈ (−1.25, −1.00) 这一 0.5 mm 的窄带里。

## 3. 设计上就该转人工的三类

不在本方法覆盖范围，列出以便识别，**不要去调参绕过**：

1. **出口面高于鼻孔面**：连通域 flood 找不到负侧种子，属复核点位问题。
2. **多序列例**：含 3D 重建、Dose Report、Scout 等非原始轴位序列。
3. **真·无点位 / 真·种子丢失**：几何本身给不出可用平面。

「escalated」是结论，不是错误码。把它改成通过只有一个办法：修上游几何或点位，而不是放宽判定。

## 4. 溯源指纹（改任何判据后必读）

每次运行给每例记录**本次实际产出的几何指纹**：`landmarks_sha256`、`surface_sha256`，并与开口阶段报告里它自报读过的 `plane_source_sha256` / `source_sha256` **交叉核对**，结果写入 `N6.provenance`（`match` / `MISMATCH` / `unrecorded`）。

**任一 MISMATCH → 该例直接 escalated**，面积照记但不作为证据。

原因是一次真实事故：某例出口面积从 268.51 变到 177.44 mm²，运行时记录只有返回码和日志尾巴，无法回答「这批到底读了哪份 surface」；而逐例详细报告会被后续批次覆盖，不能当耐久记录。**没有指纹，跨批次对账只能靠猜。**

## 5. 基准值与复验

改判据后必须先跑基准再谈结论。基准值一律**从运行记录文件里读**，禁止手抄——曾经把两条不同管线的数混记成一条基准，导致用旧管线的数去验新管线、得出假失败。

几何层公开基准（24 例批次）：默认臂 **21/24 auto_pass**，opt-in 臂（`--allow-onset-outlier`）**22/24**。通过例面积逐位不变是「本改动是严格 no-op」的证明方式。

## 6. 验收口径

正常例通过 = N1–N6 全满足且报告 `decision == "auto_pass"`。

**报告一律带 `clinical_status: generalisation_test_only_no_human_review`。自动通过 ≠ 临床可用。** 该判据只保证开口面积合理，位置是否正确需要另一套检查——面积合理与解剖位置正确是两件事，我们踩过把前者当后者的坑。
